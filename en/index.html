Layer 01 · KPI

Fix the overall baseline first

Placed at the top so every sheet below is compared with this baseline. Track count uses COUNTD instead of row count to prevent double counting.

Layer 02 · Ranking

Top N filter + horizontal bars

Instead of listing all 114 genres, only the top 10 are shown. Horizontal bars fit the long genre names, and value labels remove the need to read an axis.

Layer 03 · Relationships

Two scatter plots as evidence

A track-level danceability × popularity plot (with trend line) shows the “weak correlation,” and a genre-level danceability × energy plot shows the “clear differences between genres.”

Design Rule

A single green palette

Only one color, #1DB954, is used, with emphasis through saturation and size. No legend is needed, and the ranking still reads in black-and-white print or for color-blind users.

Why COUNTD — The same track_id appears in rows for several genres. Counting rows would show 113,999 tracks, a 27% overcount. If a COUNT-based KPI had gone out as it was, the very first line of the dashboard would have shown a wrong number.

05 · ANALYSIS

Reading the dashboard from top to bottom

Interpreting distribution, genres, and feature relationships together explains more than any single metric.

Finding 01

Popularity clusters at the middle or lower end

The mean is 33.24 and the median is 35, and 74.2% of all tracks fall between 0 and 49. Only 1.05% score 80 or above.

Finding 02

Genres differ clearly

pop-film (59.28) and k-pop (56.95) are more than 23 points above the overall average, and even #10 in the top 10 stays in the 47s.

Finding 03

Weak links to any single feature

All correlations between popularity and audio features are |r| < 0.1 (largest: instrumentalness −0.095), and the scatter plot trend line is almost flat. Factors outside the music itself also affect popularity.

Finding 04

The aggregation level changes the visible pattern

The track-level scatter plot is a wide cloud that is hard to read, but averaging by genre reveals clear clusters on the danceability × energy plane.

Popularity is explained only when genre and audio features are viewed together, at the right level of aggregation.
06 · CONCLUSION & INSIGHTS

Count the data correctly, arrange it correctly,
and the screen tells the conclusion

Audio features alone cannot fully explain popularity. A recommendation system needs to reflect both music features and user behavior.

Conclusion 01 · Analysis

No single feature explains popularity

Genre and context need to be considered together.

Conclusion 02 · Visualization

A wrong aggregation rule makes the dashboard lie

Without COUNTD, the track count is inflated by 27%. Clear definitions are what make a dashboard trustworthy.

Conclusion 03 · Next

Recommendations need user data

Artist, release date, listening history, and personal taste can complement the popularity score.

Limitations
  • Each genre is a sample of 1,000 rows, so the data does not represent Spotify’s full catalog.
  • Popularity is a snapshot at collection time and is weighted toward recent plays.
  • Correlation analysis used only Pearson coefficients, so non-linear relationships were not checked.
  • Average KPIs are row-based, so tracks listed under several genres are counted more than once. Recalculated per track, they are 33.20 · 0.56 · 0.63.
  • The 450 exact duplicate rows were kept. Removing them changes average popularity to 33.32, and only #9 and #10 of the top 10 (pop ↔ sertanejo) switch places.
